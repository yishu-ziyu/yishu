# exp3 TTS — MiniMax vs StepFun (2026-09-04)

## Method

Companion bake-off for 奕枢. Vendors with keys on this machine: MiniMax t2a_v2 and StepFun HTTP TTS.

- Node 22 `fetch`. Secrets from `apps/clicky/worker/.dev.vars` at runtime; values never written (key lengths: MiniMax 125, StepFun 65).
- MiniMax body copied from `apps/clicky/worker/local-server.mjs` (`language_boost: Chinese`, clone voice, mp3). Product today: `MINIMAX_TTS_MODEL=speech-2.8-hd`, `stream:false`. This run also measures `stream:true` hex SSE with `stream_options.exclude_aggregated_audio=true`.
- MiniMax models: `speech-2.8-turbo`, `speech-2.8-hd` (both accepted; no 2.6 fallback). Host `api.minimaxi.com`. Voice id length 22 (product clone).
- StepFun: `https://api.stepfun.com/v1/audio/speech` failed over; locked `https://api.stepfun.com/step_plan/v1/audio/speech`. `stepaudio-2.5-tts` ok. `step-tts-mini` and `step-tts-2` → HTTP 404 on this key. Voice `wenrounansheng` (温柔男声, official 情感陪伴).
- t_first_audio_ms = request start → first usable audio bytes (MiniMax stream: first non-empty hex chunk; StepFun SSE: first base64 `speech.audio.delta`; MiniMax nostream: JSON parse, so t_first = t_total).
- Duration: MiniMax `extra_info.audio_length` when present, else `afinfo`. realtime_factor = t_total / audio_duration.
- Sentence 1: 10 runs; 2–6: 5. Emotion A/B on 3–6: 5 runs, streaming only. Max 2 retries.
- MiniMax emotion enum (T2A docs): happy/sad/angry/fearful/disgusted/surprised/calm/fluent/whisper. Docs: `fluent`/`whisper` are 2.6-only; 2.8 rejects `whisper`.
- MiniMax 2.8 interjections (docs, half-width parens only): `(laughs)` `(chuckle)` `(coughs)` `(clear-throat)` `(groans)` `(breath)` `(pant)` `(inhale)` `(exhale)` `(gasps)` `(sniffs)` `(sighs)` `(snorts)` `(burps)` `(lip-smacking)` `(humming)` `(hissing)` `(emm)` `(sneezes)`. Bracket forms probed because the brief used `[laughs]`.
- StepFun 2.5: global `instruction` + inline `（…）` (docs: not spoken). HTTP `stream_format=sse`. WebSocket `/v1/realtime/audio` not measured (docs: 2.5 WS quality may be much worse than HTTP).

## Caveats

- One machine, one evening, MiniMax RPM ~dozens/min (1002 if bursted). First request after idle is slower.
- MiniMax clone vs StepFun stock `wenrounansheng`: timbre is not a fair A/B. Latency and control are.
- MiniMax nostream t_first = t_total by construction (hex inside JSON).
- Streamed MP3 duration from vendor `audio_length`; concatenated hex can confuse `afinfo`.
- Duration delta ≠ perceived emotion. Use `blind-short/` for a single sitting.
## StepFun Step Plan WS

Protocol from [ws-audio](https://platform.stepfun.com/docs/zh/api-reference/audio/ws-audio): wait `tts.connection.done` → `tts.create` (wav / 16 kHz / `mode=sentence`) → `tts.text.delta` + `tts.text.done` → collect `tts.response.audio.delta` until `tts.response.audio.done`.

Voices: `system_voices` 404/402. `GET /step_plan/v1/audio/voices` → 200 with 15 cloned `voice-tone-*` ids (not used). Official system ids `linjiajiejie` and `cixingnansheng` both synthesized. Primary: `linjiajiejie` (邻家姐姐).

## Recommendation

Streaming default remains **MiniMax `speech-2.8-hd` + `stream:true`** (product clone; s1 t_first p50 676 / p95 766). StepFun Step Plan WS (`linjiajiejie`) is not slower to first audio on the ack (p50 **664** / p95 **707**; after-text 468). It *is* slower to finish (t_total p50 1379 vs MiniMax HD stream 985; s1 duration 1280 so rtf ≈ 1.08). `instruction` moved the signal on 4/4 directed sentences: s3 Δrms +0.013 (louder), s4 Δdur **+1120 ms** and Δrms −0.008 (slower/quieter — matches 「放轻、放慢」), s5 +400 ms / −0.011 rms, s6 +320 ms / −0.005 rms. Those are objective envelope changes, not a listen score. First-audio is not the reason to refuse StepFun WS; timbre (stock 邻家姐姐 vs MiniMax clone) and higher t_total are. Owner decides expressiveness on `blind-short/`.
