## Caveats

- Network: StepFun HTTP api.stepfun.com; StepFun WS api.stepfun.com; MiniMax TTS api.minimaxi.com. Failures after 1+2 retries are recorded as rows, not retried further.
- Method A upstream streams SSE deltas (15/15 successful trials). The product proxy currently buffers the full SSE before returning text.
- Method B uses the dedicated realtime ASR socket `wss://api.stepfun.com/v1/realtime/asr/stream` (model stepaudio-2.5-asr-stream). Client VAD is off; key-up is `input_audio_buffer.commit`. If that socket returns 402, the conversation realtime API is probed as a workaround.
- This StepFun key is on Token Plan HTTP ASR (method A works) but WebSocket realtime returned HTTP 402. Conversation realtime (wss://api.stepfun.com/v1/realtime?model=step-audio-2-mini) also 402. Method B did not stream audio.
- Apple Speech status is notDetermined (supportsOnDeviceRecognition=true). This CLI skips requestAuthorization because that TCC-crashes when Cursor is the responsible process. Recorded as permission not granted. Run the binary from Terminal.app to grant Speech Recognition if you want C numbers.
- CER strips Unicode punctuation/symbols/whitespace then lowercases; English product names are compared as letters.
- TTS durations are whatever MiniMax produced at speed=1; they are close to the 2/4/8/12/15 s targets but not exact.
