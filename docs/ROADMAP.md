# 路线图

产品一句话：奕枢是 Mac 原生语音伴侣。按住 Control+Option 说话，它看得见屏幕、能真的动手操作电脑和浏览器、能按例程自己干活，用你本机已登录的模型订阅，每步动作留可验证证据。价值函数：越像《Her》越好，全部翻成可观测数字。

领导权：架构与核心判断归主代理；用户定价值、裁人评。其他 Agent 只在验收卡的标准内干活，不改架构、协议、卡。缺一个价值判断就停下来写进 `docs/NOTES.md`「待主代理」，不要猜。

三个来源各取什么：Clicky 的菜单栏语音外壳（已是身体）；nuphus 的通用电脑操控词汇（M1）；grok-bot 的说话规则（M0）、对话界面（M2、M5）、推理路由与 MCP（M3）、例程（已完成）。

## 每个节点怎么验收

统一规则见 `docs/METHODOLOGY.md`：动手前卡是 active；机器项全绿才交付；人评项列清单给用户；真机 `/Applications/奕枢.app` 用户路径通了才算过；过了由 shell 子代理提交，message 引用卡。

各节点的硬条（失败 = 没做完），细则在卡里：

- M0：真机 30 轮，实时对话档首字 p50 ≤1.0 s、首声 ≤1.5 s；说话 ≥2.5 s 的轮次 80% 边说边出字；插话 ≤100 ms 停声；工具轮次 100% 先应答；模型轮次无固定台词；用户盲听「像人」≥4/5。
- M1：新增动作全部有分层验证结果；不可逆动作 0 次未经门执行；屏幕文字注入 0 次触发不可逆动作；真机 30 步操控剧本成功 ≥90%、假完成 0。
- M2：打字与语音走同一 `turn.start`；流式渲染；先应答再工具行 100%；例程结果进对话流；重启历史可见；runtime 重启后后台结果恰好送一次。
- M3：一个真实深任务经 Claude Code 完成，期间每次许可请求都经奕枢的门；深任务自动路由在 40 条标注语句上精确率 ≥90%；MCP 客户端（Cursor 或 inspector）能列出并调用奕枢工具。
- M4：改 `记忆.md` 30 s 内召回体现；「我不喝绿茶了」后旧事实不再召回；「上周聊过什么」有带日期的回答；召回预算 ≤300 ms 不退化。
- M5：「派个帮手去查 X」→ 侧栏出现具名帮手 → 做完汇报第一人称 → 删除消失；群组三方轮流说；桌面锁同一时刻只有一个执行者。

## 不做

云端多人房间、VNC 电脑视图、壁纸、Slack/GitHub 云监听、Docker 沙箱、Cursor 私有协议、读别家 CLI 的 token、Apple 本机听写、StepFun realtime 当对话角色（重开条件见 M0 卡）。

## 给来干活的 Agent 的手册

1. 开工前按顺序读：`AGENTS.md` → `docs/NOTES.md` 头部 → 这份路线图 → `docs/ARCHITECTURE.md` → 你要做的那张卡 → `docs/PRODUCT.md`。
2. 只领卡上有编号的标准，按 `ARCHITECTURE.md` 的文件归属切分干活。卡没 active、或标准没 evaluator，不动手，写进 NOTES「待主代理」。
3. 交付报告固定四块：改了什么（按标准编号）、改了哪些文件、本地检查结果（命令 + 退出码 + 数量）、没做完与原因。不写形容词。
4. 必须停下来的情况：要改协议 schema、要改安全门分级、要新增依赖或运行时、要动 bundle id / 签名 / TCC、发现卡上的 evaluator 与真实路径不一致。
5. 不碰：`.dev.vars`、钥匙串、`.work/`、别人正在改的文件、真机安装与启动。
6. 用词具体：写部件名和它做的事，不用「脸」「嘴」「大脑」一类代称。
