# 2026-09-06

## Issue #25：键盘 PTT/听写会话从 CompanionManager 抽出

- 改了什么：新增 `YishuVoiceSessionController` 作为键盘 PTT + 听写会话的唯一所有者；`CompanionManager` 改为消费类型化会话事件。
- 为什么：#24 的第一刀。全双工不能安全加在「麦克风生命周期、runtime 取消、截图、TTS、overlay」仍挤在同一个 manager 里的现状上。本 issue 只抽输入/会话边界，不改插话语义。
- 结果：pressed/partial/released/final 一次提交、快按快松、过期回调、cancel、空终稿五条会话测绿；既有 barge-in / held-scene / transcription reducer 覆盖仍绿；CompanionManager 4507→4453 行。
- 被推翻的路：把产品事件处理放到 `CompanionManager+Voice.swift`。那些方法大量是 `private` 文件内可见，为接线去放宽访问会比把消费端留在 `CompanionManager.swift` 更差。

## PR #26 审阅：听写观察泄漏

- 改了什么：去掉 `dictationManager` 逃生口；控制器发布只读 `YishuVoiceCapturePhase`；CompanionManager 只订该投影。
- 为什么：审阅指出产品层仍直接订 `BuddyDictationManager` 的 preparing/recording/finalizing，等于旧依赖还活着。
- 结果：投影优先级与旧四旗判断一致；CompanionManager 对听写类零引用；棘轮 4446/4609，未抬。
- 被推翻的路：经协议把 Combine publisher 再转一层。existential 上的 computed `AnyPublisher` 在测试里不刷新相位；改成控制器在自己的 start/stop/cancel/final 边界重算投影。

## Issue #27：runtime stdio 传输从 YishuAgentRuntimeClient 抽出

- 改了什么：新增 `YishuRuntimeStdioTransport` 拥有 sidecar Process、三根管道、stdout 换行分帧、stderr 排空；client 只编码命令、解码行、保留 turn/RPC/watchdog。
- 为什么：#24 的第二刀。任务生命周期不能安全加在「进程管道」和「协议语义」仍挤在同一个 client 里的现状上。
- 结果：分帧/发送/启停/终止一次/stderr 不进产品输出测绿；既有 barge-in 与进程死亡 RPC 覆盖仍绿。client 3900→3861 行。
- 被推翻的路：把 JSON 编码也塞进传输。Issue 要求 payload 字节不被改写，换行是传输的唯一附加。
