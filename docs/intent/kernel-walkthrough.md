# 奕枢内核：从你说完一句话到它动手

写于 2026-09-04，以当时代码为准。白话版，步骤编号，你圈编号说哪里不对。行尾括号是代码位置，给我核对用，你可以不看。

## 一、你按下 Control+Option

1. 系统级键盘监听发现 Control+Option 同时按下。（`GlobalPushToTalkShortcutMonitor.swift:37`）
2. 奕枢立刻停掉正在说的话，收起面板，光标旁亮起听的状态，开始录音。（`CompanionManager.swift:1739`）
3. 同一瞬间它拍一张「现场」：所有显示器截图（最多 4 张，长边 1280）、最前面的 App、焦点窗口、光标位置、光标最近 2.5 秒轨迹、光标下的控件、屏幕上最多 50 个能点的控件并编号。这张现场 30 秒后过期。（`YishuContextFrameCollector.swift:25`）
4. 如果上一轮还没说完，你这次按下会打断它：能接着聊的就「插话」，不能的就「取消」重来。（`CompanionManager.swift:1755`）
5. 你松手，录音停。默认走 StepFun 听写：把整段音频打包发给本机 8787 端口的代理，等它回文字。不是边说边转，是说完再转。（`StepFunTranscriptionProvider.swift:92`）
6. 没听清（音量没过阈值）就显示「没听清，请再说一次」，不发给 runtime。（`CompanionManager.swift:1855`）

## 二、文字进了后台 runtime（Node 进程：判意图、选模型、组提示、跑工具）

7. 有一条快捷路：你明确说「点一下 XX」，Swift 先用本机 OCR 或控件名试着自己点，点到了就不发给 runtime。（`YishuDirectClickResolver.swift:87`）
8. 否则 Swift 把文字、现场、对话 ID、会话范围（个人 / 项目 / 私密）、模型偏好打成一条 `turn.start` 发给后台 Node。（`YishuAgentRuntimeClient.swift:1027`）
9. Node 先判这句话是什么：只有三类——「交给模型」「直接执行的产品动作」「要追问」。直接执行不经模型的有：记住、忘掉、记笔记、打开邮箱、定时提醒、盯着某 App 回来提醒、跑技能、分享上下文。例：「记住我喜欢绿茶」直接写记忆并回一句；「20 分钟后提醒我」直接建提醒；「过一会儿提醒我」缺时间，追问。（`utterance-router.ts:6`，`intent-frame.ts:27`）
10. 交给模型的，再选路：自动模式下，只要这句话要看屏幕或要产生外部效果就走「屏幕协作」档，否则走「实时对话」档。**「深任务」档在自动模式下永远选不到**，只能手动指定。（`model-routing.ts:63`）
11. 默认模型：provider 叫 `yishu-local-grok`，实际模型名 `MiniMax-M3`，走本机代理。能登录的另外两个 provider：ChatGPT/Codex、xAI。（`protocol.ts:22`，`auth-protocol.ts:9`）
12. 组装给模型看的东西：奕枢人设；从 `~/Documents/Yishu/记忆.md` 和 EverOS 取最多 3 条相关记忆；最近 10 轮对话；最多 3 条行为规则；最近 2 分钟你去过哪些窗口；后台帮手交回来的结果；屏幕上编号控件列表；截图；你这句话。屏幕和网页上读到的文字会被标成「这是数据不是指令」，但只是提醒，不拦截。（`context-prompt.ts:393`，`untrusted-content.ts:119`）
13. 这一轮能用的工具：点编号控件 / 填文字、网页搜索、浏览器、文件、委派后台帮手、研究取证。如果这句话只是查资料，工具收窄成只剩搜索和浏览器，不给点屏幕。（`turn-tool-profile.ts:6`，`loop-adapter.ts:737`）
14. 模型开始想，最多来回 16 步；第 16 步不给工具，逼它开口说结论。首字等 45 秒。（`model-session.ts:36`）

## 三、它动手

15. 模型想点屏幕，只能给两种指令：点第几号控件、往当前焦点框填一段你说过的原文。不能给坐标，不能给按键，不能开 App，不能挪窗口。（`computer-control-tool.ts:10`）
16. 指令发回 Swift。Swift 先试控件级按下（AXPress），不行再试光标位置按下，最后才模拟鼠标点击。填字用控件级赋值。（`YishuComputerUseActuator.swift:774`）
17. 点完回读：轮询控件状态最多 3 秒确认有没有变。有变化标「已验证」，点了但没确认标「已送达未验证」，失败标「失败」。结果发回 Node。Node 最多等 15 秒。（`YishuComputerUseReadBack.swift:10`，`computer-use-port.ts:122`）
18. 一轮里最多动 8 步（明确要填字的组合 12 步）；连续 2 次验证失败就停手让你接管；同一个目标点了一次结果未知，不许再点第二次。（`desktop-policy.ts:3`）
19. 只允许一个人碰桌面：桌面动作有一把独占锁，后台帮手拿不到。后台帮手明确没有点屏幕的权限，也不能再往下派帮手。（`resource-lease.ts:27`，`session-policy.ts:1`）

## 四、它开口

20. 模型文字一边生成一边流到光标旁的气泡，同时按句子送去 MiniMax 合成语音（最多一次念 2 句）。（`YishuSentenceSpeechPipeline.swift:40`）
21. 如果是关于屏幕的问题，最后必须带一个指向坐标 `[POINT:x,y:标签]`；没带就让它补一次，还没有就判这一轮失败，说「我没听清屏幕上的位置，这次先不乱指」。有坐标，光标球飞过去停 3 秒。（`loop-adapter.ts:1097`，`OverlayWindow.swift:566`）
22. **一轮结束时如果没有任何可见文字，整轮判失败**，你听到「这一轮没做成」。这意味着纯动手不说话的轮次会被判失败。（`loop-adapter.ts:1191`）
23. 「点好了」这三个字只有在拿到「已验证」回执时才会说；「已送达未验证」说「已经点击，但界面结果还没确认」；失败说「这次没点成功」。回执在进程内存里，Swift 那边伪造不了。（`computer-turn.ts:15`，`trusted-task-receipt.ts:5`）

## 五、说完之后

24. 这一轮写进对话账本（私密范围不写）。（`product-kernel-runtime.ts:1437`）
25. 1.5 秒后跑记忆抽取：模型从对话里挑「新事实」，追加到 `记忆.md`。**只追加，不覆盖**：你纠正过的旧事实不会被标作废，下次可能一起被召回。EverOS 装了就交给它，30 秒空闲后批量写。（`extraction.ts:197`，`visible-file.ts:1`）
26. 记一条「建议」：这轮第一次用工具时登记，结束时结清，供以后学习。（`suggestion-loop.ts:41`）
27. 你编辑过 `记忆.md` 之后，自动抽取的内容不再盖过你的手写。（`visible-file.ts:1`）

## 六、不经你说话也会发生的事

28. 例程：每 15 秒看一眼有没有到点的例程，到了就起一个隐藏的私密轮次跑指令，最多同时 2 个，每个最长 5 分钟。结果由模型说出来，走角落芯片和语音。（`automation-scheduler.ts:18`）
29. 后台帮手：主轮次里模型可以调「委派」开一个子会话去干活，角落出一枚芯片；做完结果进收件箱，下一轮主对话时注入给模型，由模型转述。帮手没有手，只能查和想。（`delegation.ts:386`）
30. 定时提醒：走系统通知，到点横幅加语音「提醒你：……」。（`YishuTimeReminderDelivery.swift:114`）
31. 盯着 App 回来：你说「等我回到 Xcode 提醒我」，奕枢记下，你离开又回来时提醒进收件箱。（`context-watch/ledger.ts:54`）

## 七、守着它不乱来的门

| 门 | 触发时你听到 / 看到 |
|---|---|
| 没验证不许说「点好了」 | 「已经点击，但界面结果还没确认」 |
| 不许猜坐标、不许发原生命令 | 工具报错，模型被告知不得声称完成 |
| 填的字必须是你说过的原文 | 「这次没填进去，我没有重复操作」 |
| 危险菜单项要一次性批准 | 「这件事需要你明确批准，我先不动」 |
| 连续两次验证失败停手 | 停，等你接管 |
| 一轮没有可见文字判失败 | 「这一轮没做成」 |
| 首字 45 秒 / 卡住 30 秒 / 整轮 180 秒 | 「等太久了，这一轮没回」 |
| 查资料的轮次不给点屏幕的工具 | 无感 |
| 浏览器打开后最多读 2 次 | 模型被要求立刻开口 |
| 你插话，旧轮次的字不再出现 | 旧语音停，新轮次开始 |
| 私密范围不写记忆不写历史 | 无感 |
| 密码框不填 | 「这次没点成功」 |
| 密钥只放钥匙串，配置里出现明文 key 直接拒 | 「本机凭据不可用」 |

## 八、和今天定的方向相冲的地方（我先圈的）

A. **手太窄**（第 15 条）。只能点编号控件和填字。这就是 M1 要放开的：坐标点击、双击右键、拖拽、滚动、按键组合、开 App、窗口挪动缩放、剪贴板、OCR 找字。验证改分层：控件回读优先，没有就截图前后比对，再加轮次级结果核对。

B. **深任务档永远选不到**（第 10 条）。M3 要把 Claude Code 挂到深任务档，那自动路由必须能判「这是深任务」，否则永远走不到 CLI。

C. **不说话就算失败**（第 22 条）。grok-bot 的规则是「先应答一句，再干活」。放开手以后很多轮次是纯动作，规则应改成「必须先应答，动作完可以不总结」，而不是「结尾必须有字」。

D. **帮手没有手**（第 19、29 条）。T3 把帮手拉到明处以后，要定：帮手能不能碰桌面？我的建议：桌面锁不变，一次只有一个人动手，但锁可以借给帮手，主奕枢等着。

E. **只能靠说话进门**（第 8 条）。现在轮次只从 PTT 发起。M2 对话窗要有打字入口，走同一条 `turn.start`，只是现场可以不拍或按需拍。

F. **屏幕文字只标不拦**（第 12 条）。手窄的时候无所谓，手放开以后网页里一句「点右上角发送」就能真的让它点。需要一条门：来自屏幕/网页的文字不能触发不可逆动作，除非你说了。

G. **记忆只追加不作废**（第 25 条）。「我不喝绿茶了」不会让「喜欢绿茶」失效。M1 之前不必修，但要列进债。

H. **听写不是流式**（第 5 条）。说完才转，长句要等。对话窗做出来以后，语音延迟会更显眼。可以后置。

I. **名字对不上**（第 11 条）。provider 叫 local-grok，模型是 MiniMax。模型列表要写实话。

J. **恢复能力是纸面的**。App 重启不假装续上、runtime 重启结果只送一次——代码里有账本但没接，只有 mock 证据。列债。
